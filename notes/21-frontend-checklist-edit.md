# 画面：チェックリストの編集

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/checklist.ts` | チェックリストの操作（普通の関数）。`addItem`（足す）、`removeItem`（消す）、`setDone`（チェック）、`mergeTemplate`（テンプレートを後ろに足す。同じ名前は重ねない）、`sameChecklist`（同じ内容か） |
| `frontend/src/components/RequestDialog.vue` | 右側のチェックリスト。チェックボックス、「×」で消す、「項目を足す」の入力欄（Enter または「＋」）、「テンプレートを入れる」ボタン |
| `frontend/src/requestForm.ts` | 入力欄にチェックリスト（`checklist`）を持たせた。`formToPatch` は、変わっているときだけ `checklist_items` を送る |
| `frontend/src/api.ts` | `fetchTemplateItems`（`GET /api/categories/{id}/template-items`） |

チェックの操作は、画面の中（入力欄）だけで行い、「保存」を押したときに、ほかの項目と一緒に保存する（仕様の UC-2 のとおり）。新しい依頼でも、保存前に、その場でチェックリストを作れる。

## 学んだこと
- **操作の関数は、元の配列を書き換えず、新しい配列を返す**：Vue は「新しい配列に入れ替わった」ことで、画面の更新に気づきやすい。元を書き換えると、「元の値」と比べられなくなる（変えたかどうかが分からなくなる）
- **「変わったか」を調べて、変わったときだけ送る**：`checklist_items` は、送ると「その一覧にそっくり入れ替わる」API。変えていないのに送ると、別の画面で変わっていた内容を、うっかり上書きするおそれがある。開いたときの値と比べて（`sameChecklist`）、変わったときだけ送る
- **「同じ配列を返す」ことで、変化の有無を伝える**：`mergeTemplate` は、足す項目が1つもなければ、渡された配列を**そのまま**返す。呼ぶ側は `merged === 元の配列` で、「何も増えなかった（もう全部入っている）」と分かり、お知らせを出せる
- **日本語入力の Enter**：変換を確定するための Enter でも、`keyup` や `keydown` のイベントが起きる。そのまま「項目を足す」にすると、変換の途中の文字が追加されてしまう。`event.isComposing`（変換中か）を見て、変換中は無視する
- **画面で直しても、元の値は変えない**：開いたときのチェックリストは、コピーして入力欄に入れる（`detailToForm`）。コピーしないと、画面でチェックを付けたとき、「元の値」まで変わって、比べられなくなる（テストで確認した）
- **項目の「キー」は、番号を使う**：チェックリストの項目は、同じ名前が複数あってもよい。名前をキーにすると重なるので、並びの番号を使った

## 要件にない、私（Claude Code）が決めた点
- テンプレートがない、または、すべて入っているときは、チェックリストの下に、小さくお知らせを出す
- カテゴリーを変えても、すでに入っている項目は、そのままにする（テンプレートは、ボタンを押したときだけ入る）
- 「テンプレートを入れる」は、カテゴリーが未選択のときは、押せない
- 新しい依頼のモーダルにあった「保存したあとで追加します」の表示は、なくした

## 確認が必要なこと
- ブラウザで、見た目と動きを確認する（私は、ブラウザを操作できない）
- 本物の API で、チェックリストつきの追加・チェックの更新・「送らない更新では変わらない」ことと、一覧の進み具合（例：1/3、2/2）を確認した（確認用のデータは、元に戻した）
