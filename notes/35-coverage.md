# カバレッジ：テストが、コードのどこまで通ったか（画面）

品質チェックの「道具の追加」の4つ目（[docs/quality-review.md](../docs/quality-review.md) の 5 章）。バックエンドと画面を、別の PR に分け、まず画面を作った。設定は `frontend/vite.config.ts`。

## カバレッジとは
テストを動かしたとき、コードの**どの行・どの分岐が、実際に実行されたか**の割合。`npm run test:coverage` で測る。詳しい表は、`frontend/coverage/index.html` をブラウザで開く（通らなかった行が、赤く見える）。

| 用語 | 意味 |
|---|---|
| 文（Statements） | プログラムの1つ1つの命令の、実行された割合 |
| 分岐（Branches） | `if` の「はい」「いいえ」の、両方を通った割合。いちばん低くなりやすい |
| 関数（Functions） | 呼ばれた関数の割合 |
| 行（Lines） | 実行された行の割合 |

## 測った数字（2026-11-08）
| 全体 | 文 | 分岐 | 関数 | 行 |
|---|---|---|---|---|
| 割合 | 64.71% | 76.18% | 64.44% | 66.61% |

**中身は、偏っている。**
- 関数だけのファイル（`api.ts`、`checklist.ts`、`display.ts`、`order.ts`、`templateEdit.ts`、`categoryManage.ts`）は、ほぼ **100%**
- 部品は、中程度：詳細モーダル 67%、カテゴリー管理 88%、テンプレート編集 76%、確認先の入力 81%、一覧（`RequestTable.vue`）48%
- **`App.vue`、`RequestFilters.vue`、`SummaryChips.vue` は、0%**。部品のテストを、まだ作っていない

## 作ったもの・変えたもの
| 場所 | 中身 |
|---|---|
| `frontend/vite.config.ts` | カバレッジの設定：対象、外すもの、レポートの形式、しきい値 |
| `frontend/package.json` | `test:coverage` と、`@vitest/coverage-v8` 5.1.0（版を固定） |
| `.github/workflows/ci.yml` | CI の frontend ジョブで、`npm run test` を、`npm run test:coverage` に置き換えた |
| `.gitignore`・`frontend/.prettierignore`・`frontend/eslint.config.js` | レポートのフォルダ（`coverage/`）を、除外 |

## 学んだこと
- **しきい値は、測った数字より、少し下に置く。** 文 60・分岐 70・関数 60・行 62。**あとで、テストを書かずにコードを増やしたとき、割合が下がり、CI が気づかせてくれる**。ぴったりにすると、小さな変更でも失敗して、うるさい。**わざと高い値（行 95%）にして、本当に失敗する**ことも確かめた（「行の 66.61% が、しきい値 95% に届かない」と出て、終了コード 1）
- **100% は、目指さない。** 数字を上げるために、意味のないテストを書くのは、本末転倒。**「カバレッジが高い ＝ 品質が高い」ではない**。「通った」だけで、「正しく確かめた」とは限らない（`expect` のないテストでも、数字は上がる）。**低い所を見つける道具**として使う。今回は、`App.vue` などが 0% だと、数字で分かった
- **測る対象を、決める。** テスト自身、テストの道具、起動の入口（`main.ts`）、型の宣言だけのファイルは、外した。**理由を、設定に書いた**。測る意味のないものを入れると、数字が、実態より低く（または高く）見える
- **表は、省かずに、すべて出す。** 最初は、100% のファイルが、表から省かれていた（`api.ts` などが、一覧にない）。「省かれている＝テストがない」と、読み間違えやすい。`skipFull: false` で、すべて出すようにした
- **レポートのフォルダは、ほかの道具の対象から外す。** `coverage/` には、HTML や JavaScript が、大量に作られる。外さないと、**整形チェックや lint が、レポートまで調べて、失敗する**。Git にも入れない（`.gitignore`）。**`.gitignore` では、行の途中にコメントを書けない**（`coverage/ # 説明` と書くと、全体が1つの名前と見なされ、除外が効かない）。コメントは、別の行に書く
- **道具の版は、そろっていないと動かないことがある。** `@vitest/coverage-v8` は、入っている `vitest` と、**まったく同じ版（5.1.0）**でなければ動かない。これまでは、「公開から2週間以上たった版」を選ぶ方針だったが、5.1.0 は公開から5日だった。**ルールを、状況で、例外にする**ときは、理由を説明して、ユーザーに了承をもらい、記録に残す（ユーザーが了承）
- **CI でも、測る。** しきい値を置いても、CI で動かさなければ、意味がない。`npm run test` を、`npm run test:coverage` に**置き換えた**（テストは、1回だけ動かす）。ジョブの名前は、変えていない（必須チェックが、見つからなくならないように）

## これからのこと
- **バックエンドのカバレッジ**（`pytest-cov`）：別の PR
- **画面の 0% の部品**（`App.vue`、`RequestFilters.vue`、`SummaryChips.vue`）と、一覧：部品のテストを足すと、割合が上がる。上がったら、しきい値も上げる

## やってみよう
1. `frontend/` で `npm.cmd run test:coverage` を実行し、表を見る
2. `coverage/index.html` をブラウザで開き、`RequestTable.vue` の、赤い行（通らなかった行）を見る
3. `vite.config.ts` の `lines: 62` を、一時的に `lines: 95` に書き換えて、実行する。失敗することを確かめたら、元に戻す
