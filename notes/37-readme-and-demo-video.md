# README の書き直しと、画面録画（動画）

Issue #127。自分が作業するための手順書だった README を、**初めて見る人（採用の場面で見る人、ほかの開発者）**向けに、書き直した。あわせて、動きが分かる画面録画（GIF と MP4）を入れた。

## README で学んだこと

- **誰に向けて書くかを、先に決める。** 今まで、README は「自分が、次に何をするか」のための手順書だった。読む人を、「初めて見る人」に決めると、順番が変わる：①何ができるか（ひとこと）→ ②動き（動画）→ ③特徴 → ④技術と、作り方 → ⑤動かし方。**知りたい順に、並べる**
- **いちばんの特徴を、先頭に、短い言葉で。** このアプリでは、**「業務フローを、テンプレートとして登録しておき、ワンクリックで、チェックリストに入れられる」**こと。最初の2行に、書いた。「機能の一覧」より、「**何が、いちばん、役に立つのか**」を、先に伝える
- **書いてあることは、実際と合わせる。** できていないことは、「できている」と書かない（デプロイは、「これから」に書いた）。テスト件数やカバレッジのような、**古くなりやすい数字は、README に書かない**（記録は、品質チェックの文書に任せた）
- **名前に注意する（公開リポジトリ）。** 「業務部の担当者」という、実在の部署を思わせる表現を、ユーザーの希望で、リポジトリ全体から外した（README・要件定義・ユースケース・学習ノート）。**公開する文書は、実在の組織や人を、特定できないようにする**
- **AI を使った事実も、書く。** 「Claude Code と、対話しながら進めた。作業は AI が進め、内容の確認と、機能・技術の決定は、人が行った」。事実を、正直に書いた（どう見せるかは、ユーザーの判断）

## 画面録画（動画）で学んだこと

### GitHub の README に、動画を載せる方法
| 方法 | 長所 | 短所 |
|---|---|---|
| **GIF** | README の中で、**自動で動く** | 画質が粗く、長いと容量が大きい |
| MP4 をリンク | 画質がよい | README の中では、再生されない（リンクを押して、別画面で開く） |

**両方使う**ことにした。README には、短い GIF（19秒）を貼り、通しの MP4（2分37秒）は、リンクにした。

### 撮るとき
- **録画の方法で、映るものが変わる。** Windows の `Win + Alt + R`（Xbox Game Bar）は、**アクティブな1つのウィンドウだけ**を録画する。Chrome の**カレンダー**のような、別の小さなウィンドウは、映らない。**範囲を指定する録画**（スニッピングツールの動画）なら、映る。**映したいものが、録画の方法で映るか**を、先に確かめる
- **撮る前に、データを整える。** サンプルの依頼を、見映えのよい、架空のデータに入れ直した（API 経由で入れるスクリプト）。**期限の色は、「今日」の日付で決まる**ので、撮影の日付を考えて、日付を決めた
- **撮り直せるようにしておく。** 操作で、データが変わる（削除など）。データを**何度でも、元に戻せる手順**（`alembic downgrade base` → `upgrade head` → 投入スクリプト）を、用意した。リセットの前に、DB をバックアップした
- **ブラウザの枠は、映さない。** 拡張機能のアイコンや、通知が映ると、見映えが落ちる。**画面の範囲だけ**を指定して録画すれば、クロップも要らない

### 確認するとき（公開する前に、必ず）
- **映ってはいけないもの**（IP アドレス、アカウント ID、実在の名前、通知、ほかのタブ）が、映っていないかを、**公開する前に、確認する**（`CLAUDE.md` の約束）。**リポジトリの外に置いて、確認してから、リポジトリに入れる**（うっかり、コミットされないように）
- **動画は、フレームを抜き出して、見る。** 3秒ごとのフレームを、一覧表（コンタクトシート）にして、全体を見た。気になる所は、実物の大きさで、拡大して見た（ブラウザの上部など）
- **編集の前に、撮ったままの録画を、先に確認する。** 問題が、編集の前に分かれば、編集の時間を、無駄にしない

### 変換・編集
- **ffmpeg（動画の変換の道具）を、PC に入れない。** 使い捨ての Docker で動かした（`docker run --rm`）。ファイルは、**読み取り専用**で渡すので、元のファイルは、変わらない。使い終わったら、イメージも消す
- **GIF は、色を最適化して作る。** ffmpeg の `palettegen` と `paletteuse` で、その GIF に合う色の一覧（パレット）を作ってから、変換する。これだけで、同じ容量でも、**ずっと、きれいになる**。幅を 800px に縮め、12fps にして、19秒で、**1.4MB** に収まった
- **音声は、いらない。** 録画に音声のトラックが入っていた。**無音**でも、トラックが残っていると、容量が増える。`-an` で、取り除いた
- **画面の大きさ（縦横比）を、そろえる。** 録画が 1906×908 と、横長だった。そのまま 1280×720（16：9）に入れると、上下に黒い帯が出る。**テロップ専用の帯**を足す形にして、うまく使った（1280×720）
- **テロップは、映像の外の、帯に入れる。** モーダルやボタンに、かからない。長い文は、読めない（日本語は、1秒に 5〜7文字）ので、**1〜2行、25文字前後**にする。「操作の手順」ではなく、「何をしているか＋その良さ」を、一言で
- **音も音楽もない動画は、テロップが、親切。** フォントは、アプリと同じ Noto Sans JP（権利が、はっきりしている）にして、`CREDITS.md` に書いた。音楽は、入れない（著作権の確認が、増えるため）
- **動画の長さを、変えずに、テロップを入れる。** GIF を切り出す位置が、ずれないようにするため。テロップの**切り替わる時刻**を見て、GIF の範囲（0:49〜1:07）を、前後のテロップを含まないように、決めた

### リポジトリに入れるとき
- **容量を考える。** MP4（25MB）は、リポジトリの大きさ（それまで約 4MB）に、一度だけ、加わる。GitHub の制限は、1ファイル 100MB まで。**あとで差し替えると、その分だけ、履歴が増える**。ビットレートを、1.5 Mbps に下げて、30MB 以内に収めた
- **動画の、画面に映るのは、自分で作ったもの。** 素材の出典は、`CREDITS.md` に書いた（フォント。音楽・第三者の画像は、なし）
