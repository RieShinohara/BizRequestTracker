# デプロイの設定ファイルと、当日の手順書（デプロイの準備 2/3）

Issue #131。EC2 の中に置く設定（`deploy/`）と、当日の手順書を作った。**AWS には、まだ何も作っていない。** 手順書は、[deploy/README.md](../deploy/README.md)。構成は、[docs/infrastructure.md](../docs/infrastructure.md)。

## 作った物
| ファイル | 役割 |
|---|---|
| `deploy/nginx-bizrequesttracker.conf` | nginx の設定。`/api/` と `/health` だけを、バックエンド（8000番）に中継。`/docs`・`/redoc`・`/openapi.json` は、はっきり 404。それ以外は、画面のファイル |
| `deploy/bizrequesttracker.service` | systemd の設定。バックエンドを、サーバーの裏で動かし続ける（起動時に自動で起動・落ちたら起動し直す） |
| `deploy/seed_demo.py` | （任意）録画用に、架空の依頼を入れるスクリプト |
| `deploy/README.md` | 当日の手順書（送る → 置く → 表を作る → 起動 → 確認） |

## 学んだこと
- **「外に出さない」は、設定で、はっきり書く。** バックエンドは `127.0.0.1`（サーバーの中だけ）で待ち受け、外から来るのは nginx 経由だけ。さらに、`/docs` が、画面のファイルに置き換わって「200 で、画面が返る」ことのないよう、`return 404` と書いた。**使い捨ての Docker の nginx で、試した**（偽のバックエンドを置いて、`/docs`・`/docs/` などで、404 になること、`/api/` と `/health` が中継されることを確認）
- **パスワードは、サービスの設定ファイルに書かない。** `EnvironmentFile=/etc/bizrequesttracker.env`（権限 600）から読む。リポジトリには、置かない。アプリのコードは変えず、環境変数 `DATABASE_URL` を優先する、もともとの作りを使う
- **スクリプトは、「安全装置」を入れる。** `seed_demo.py` は、依頼がすでにあると、エラーで止まる（2回実行して、二重に入るのを防ぐ）。実際に、すでにデータのある開発用 DB に向けて、止まることを確かめた。空の DB（`alembic downgrade base` → `upgrade head`）で、依頼9件（アーカイブ1件）・依頼者5人が入り、期限の色（赤1・オレンジ2）が出ることも確かめた
- **日付は、実行する日を基準にする。** 固定の日付だと、録画する日に、期限の色が出ない。「今日から何日後」で決めると、いつ実行しても、見せたい状態になる
- **EC2 の標準の Python は古い**（3.9）。EC2 の中で動かす、`seed_demo.py` は、標準の部品だけで、書いた（追加の導入が、要らない）
