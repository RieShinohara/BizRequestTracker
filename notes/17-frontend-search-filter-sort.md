# 画面：検索・絞り込み・並び替え

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/types.ts` | 条件の型（`RequestQuery`）、並び替えの種類（`SortKey`）、カテゴリー（`Category`） |
| `frontend/src/api.ts` | `buildRequestsUrl`（条件から URL を作る）、`fetchRequests` を条件つきに、`fetchCategories` を追加 |
| `frontend/src/display.ts` | 並び替えの選択肢（`SORT_OPTIONS`）、条件が入っているかの判定（`hasActiveFilter`） |
| `frontend/src/components/RequestFilters.vue` | 検索欄、カテゴリー・ステータスの選択、「QMS のみ」、「条件を外す」、並び替えの切り替え |
| `frontend/src/App.vue` | 条件を持ち、変わったら一覧を取り直す |

検索の文字は、入力が止まってから（0.3秒後）API を呼ぶ。選択や切り替えは、すぐ呼ぶ。

## 学んだこと
- **検索・絞り込み・並び替えは、API に任せる**：画面は、条件を URL に付けて呼ぶだけ。並べ方や、検索の細かい決まり（どの項目を探すか、アーカイブ中を除く、など）は、バックエンドの1か所にある
- **URL は、`URLSearchParams` で作る**：検索の文字に `%` や `&` や日本語が入っても、安全な形に直してくれる。手で文字をつなぐと、`&` で条件が途中で切れるなどの不具合になる
- **「空の条件は付けない」**：空の検索文字や、未選択のカテゴリーは、URL に付けない。API では「省略」と同じ意味になる。カテゴリーの番号が `0` のときも条件にするため、`if (id)` ではなく `!= null` で判定した（`0` は「偽」として扱われるため）
- **デバウンス（入力が止まるまで待つ）**：1文字打つたびに API を呼ぶと、無駄が多い。タイマーを毎回やり直し、止まってから1回だけ呼ぶ
- **古い応答で上書きしない**：条件を素早く変えると、先に呼んだ分の応答が、あとから届くことがある。呼ぶたびに番号を付け、最新の番号の応答だけを画面に反映する
- **`defineModel`**：親が持つ値を、子の部品が書き換えるための Vue の仕組み。`RequestFilters` は、条件を直接持たず、親の `query` を `v-model` で受け取る
- **並び替えは「見せ方」**：選んでも、手動の並びは変わらない。「手動の並び」を選ぶと戻る
- **無関係なファイルが変わったとき**：`prettier --write .`（全体の整形）は、Windows の改行（CRLF）を直してしまい、無関係なファイルまで変わる。今後は、触ったファイルだけを指定して整形する

## 要件にない、私（Claude Code）が決めた点
- 並び替えは、「手動の並び／優先度／期限日／ステータス」の切り替えボタンにした（「手動の並びに戻すボタン」は、切り替えの1つとして入れた）
- 「条件を外す」ボタンは、条件が1つでも入っているときだけ出す。外すのは、検索・QMS・カテゴリー・ステータス（並び替えと「アーカイブも表示」は、そのまま）
- 件数（画面上部）と、カテゴリーの選択肢は、開いたときに1回だけ取る（条件の影響を受けないため）
- 条件に合う依頼がないときは、「条件に合う依頼がありません」と出す

## 確認が必要なこと
- ブラウザで、見た目と動きを確認する（私は、ブラウザを操作できない）
- API 側（検索・並び替え）は、`curl` で、期待どおりの結果が返ることを確認した
