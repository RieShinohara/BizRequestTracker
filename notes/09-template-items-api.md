# テンプレート項目の API

## 作ったもの
| 窓口 | 内容 |
|---|---|
| `GET /api/categories/{id}/template-items` | カテゴリーのテンプレート項目を、順番どおりに返す |
| `PUT /api/categories/{id}/template-items` | 送った一覧を、そのままテンプレートにする（全部入れ替え） |

場所は `backend/app/routers/categories.py`（カテゴリーの窓口の続き）。テストは `backend/tests/test_template_items_api.py`（10件）。仕様は [docs/api-design.md](../docs/api-design.md) の「7」。

## 学んだこと
- **PUT は「全部入れ替え」**：送った一覧が、そのままテンプレートになる。追加・編集・削除・並べ替えを、「保存」ボタン1回で反映できる。1つずつ追加・削除する窓口（`POST`・`DELETE`）を、項目の数だけ作らずに済む
- **順番は、並び方で表す**：送る JSON に `sort_order` は入れない。配列の先頭から 1, 2, 3… と、サーバーが振る。画面は、並べた順に送るだけでよい
- **「入れ替え」の作り方**：`category.template_items = [新しい一覧]` と代入すると、SQLAlchemy が、古い項目の削除と、新しい項目の追加を、まとめて行う（`delete-orphan`＝持ち主を失った項目は消す、という設定のおかげ）
- **途中で失敗したら、元のまま**：2件目の名前が空で 422 になっても、1件目も保存されない。入力の確認は、DB を触る前に終わるため
- **テンプレートを直しても、すでにある依頼のチェックリストは変わらない**：テンプレートは、チェック項目を作るときの「コピー元」にすぎない（data-model.md の決めごと）

## 要件にない、私（Claude Code）が決めた点
- `PUT` の返事は、保存後の一覧（`GET` と同じ形）。設計書に指定がなかったため
- 同じ名前の項目が、2つ並んでもよい（設計書に制限がなかったため）
- 項目名の長さは200文字まで。前後の空白は取り除き、空は 422
