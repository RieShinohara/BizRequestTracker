# 画面：依頼の追加

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/App.vue` | 「新しい依頼」ボタン。モーダルの状態（開いている依頼の番号／新しい依頼を作っているか）を持つ |
| `frontend/src/components/RequestDialog.vue` | 詳細モーダルを、「直す」と「新しく作る」の両方に使えるようにした（`isNew`）。保存のとき、新規なら `POST`、既存なら `PATCH` |
| `frontend/src/requestForm.ts` | `emptyForm`（空の入力欄と初期値）、`todayIso`（今日の日付）、カテゴリー未選択の確認（`CATEGORY_MESSAGE`） |
| `frontend/src/api.ts` | `createRequest`（`POST /api/requests`） |

## 学んだこと
- **「直す」と「作る」は、同じ部品を使い回せる**：違うのは、最初の入力欄の中身（取ってくるか、空にするか）と、保存の呼び方（`POST` か `PATCH` か）だけ。入力欄・確認・送る形への変換は、同じ。部品を2つに分けるより、直す所が少なくて済む
- **`watch` の入力を、まとめて1つにする**：「どの依頼を開いたか」と「新しく作るか」の2つが変わったら、中身を作り直す。`() => [props.requestId, props.isNew] as const` のように、配列で返す
- **古い結果を捨てる、番号の付け方**：読み込み中に、閉じたり、別の依頼を開いたりしたら、あとから届いた結果を捨てる。以前は「依頼の番号」で見分けたが、「新しい依頼」には番号がないので、開くたびに増える**カウンター**（`openCount`）で見分ける形に変えた
- **今日の日付は、パソコンの日付で決める**：`new Date().toISOString()` は UTC なので、日本の朝（午前9時より前）は、前の日になってしまう。`getFullYear()` などで組み立てる
- **失敗したときの後始末**：新しい依頼者を登録したあとで、依頼の保存が失敗したとき、そのままやり直すと、「同じ名前の依頼者」で止まる（画面が持つ依頼者の一覧が古いため）。失敗したら、依頼者の一覧を取り直す
- **`undefined` は、JSON にすると消える**：`category_id: undefined` は、送られない。確認（`validateForm`）で止めているので、実際には起きないが、型の上で「未選択」を表せる

## 要件にない、私（Claude Code）が決めた点
- 新しい依頼を保存したら、検索・絞り込み・並び替えを外す（手動の並びの一番上に入る、という仕様を、画面で見えるようにするため。「アーカイブも表示」は、そのまま）
- カテゴリーが1つもないときは、「カテゴリーを選んでください」と出す（仕様の必須は、タイトル・依頼者・期限日。カテゴリーは、先頭が初期値になるため、通常は起きない）
- 新しい依頼のモーダルには、「新しい依頼」の見出しを付けた
- チェックリストは、保存したあとで追加する（モーダルに、その旨を出した。編集は次の Issue で作る）
