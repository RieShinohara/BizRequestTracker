## 学んだこと
- **しきい値は、測った数字より、少し下に置く**（画面と同じ）。99% に対して 95%。**わざと 100% にして、失敗する**ことも確かめた（「全体 99.09%、必須は 100%」と出て、終了コード 1）。通常の 95% では、通る
- **ふだんの `uv run pytest` には、付けない。** `--cov` を付けると、少し遅くなる（10 秒 → 14 秒）。カバレッジを測るときだけ、`uv run pytest --cov` と打つ。CI は、測る側（置き換え）。画面の `npm run test:coverage` と、同じ考え方
- **分岐も測る**（`branch = true`）。行は、全部通っても、`if` の片方（「いいえ」）だけしか通っていないことがある。バックエンドは、分岐 72 すべて通っていた。**よく作り込めている**と言える
- **代用品に差し替えた所は、本物が動かない。** テストでは、DB の貸し出し（`get_db`）を、代用品に差し替えている（`app.dependency_overrides`）。便利だが、**本物の `get_db` は、一度も動いていない**。カバレッジが、それを教えてくれた。2行だけの単純な部分で、実害は小さい（本物は、起動した API で、毎回動いている）。**「通っていない」ことと、「危ない」ことは、別**。見直すかは、判断
- **「ほぼ 100%」でも、残りを、確かめる意味がある。** 残りの 5 文は、「テストしにくい」所に集まる。**何を、テストしなくてよいと決めるか**を、自覚できる
- **版の選び方。** `pytest-cov` 7.1.0 は、公開から231日。それが連れてくる `coverage` は、最初、最新の 7.17.2（公開から3日）が入った。**間接的に入る部品も、版を見る**。公開から2週間以上たった 7.17.0（16日）を、直接固定した（`uv add --dev "coverage==7.17.0"`）。固定は、`uv.lock` にも反映される
- **`.coverage` ファイルを、Git に入れない。** カバレッジを測ると、`.coverage`（記録）が作られる。ほかの生成物と同じ扱いで、`.gitignore` に入れた

## これからのこと
- カバレッジの数字が上がったら、しきい値も上げる（画面は、`App.vue` などが 0%。バックエンドは、ほぼ上限）
- 画面側は、部品のテストを足すと、割合が上がる（[35-coverage.md](35-coverage.md)）

## やってみよう
1. `backend/` で `uv run pytest --cov` を実行して、表を見る。`Missing` の列に、通っていない行の番号が出る
2. `app/deps.py` を開き、10-11行を読む。なぜ、テストで通らないのか考える（`tests/conftest.py` の `dependency_overrides`）
3. `pyproject.toml` の `fail_under = 95` を、一時的に `100` に書き換えて、実行する。失敗することを確かめたら、元に戻す
