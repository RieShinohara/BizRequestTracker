# 画面：テンプレート編集

品質チェックの D2（[docs/quality-review.md](../docs/quality-review.md)）の2つ目。UC-9 の画面。これで、要件の画面の機能は、そろった。API（`GET`・`PUT /api/categories/{id}/template-items`）は、すでにできていた。

## 決めたこと
| 項目 | 決定 | 理由 |
|---|---|---|
| 置き場所 | カテゴリー管理のモーダルの各カテゴリーの「テンプレート」ボタンから開く（重ねて開く） | カテゴリーを選ぶ手間がなく、「作る → テンプレートを作る」（UC-10 の流れ）が、同じ場所で続ける |
| 編集のしかた | 項目の追加・名前の直し・削除を、「保存」でまとめて反映。並び替え（ドラッグ）は作らない | API の `PUT` が、「送った一覧が、そのままテンプレートになる」作りのため。ドラッグは、要件で「最初は作らない」 |

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/components/TemplateDialog.vue` | テンプレート編集のモーダル |
| `frontend/src/templateEdit.ts` | 項目の足す・消す・直す、入力の確認、変更の有無の判断（部品から切り離した） |
| `frontend/src/api.ts` | `saveTemplateItems`（`PUT`） |
| `frontend/src/templateEdit.test.ts` | 上のテスト（16件） |

## 学んだこと
- **編集中の内容は、画面の中のコピーに対して直し、「保存」で、まとめて送る。** 1項目ごとに API を呼ばない。途中で、やめることもできる。「元の内容（`original`）」と「直している内容（`names`）」を別に持つと、「変更があるか」を、比べるだけで分かる
- **保存していない変更があるときは、うっかり閉じられないようにする**（品質チェック F2 と同じ問題を、この画面では、最初から避けた）。Vuetify の `persistent` は、枠の外を押す・Esc で閉じるのを止める。`:persistent="dirty"` と、変更の有無に結び付けた。閉じるボタンは、「変更を捨てて閉じる」に変え、赤くして、捨てることを、はっきり伝える
- **書きかけの文字も、「変更」に数える。** 「項目を足す」に入力したまま「保存」を押すと、その文字が消えてしまう。保存のときに、足してから保存する。「書いたものが、黙って消える」を避ける
- **空の名前は、画面で先に、何番目かを添えて知らせる。** API も 422 で断るが、その `detail` は配列で、人が読む文ではない（前の画面の学び）。画面の検査は親切のため、API の検査が、守りの本番
- **テンプレートを空にすることも、できる。** 項目が0件の一覧も、有効な保存。`PUT` で空の配列を送る
- **「今ある依頼は変わらない」ことを、画面に書く。** テンプレートは「入れた時点のコピー」なので、あとから直しても、すでにある依頼のチェックリストは変わらない。使う人が、「直したのに、依頼が変わらない」と戸惑わないように、説明を、画面の上に置いた
- **読み込み中に、閉じた・別のカテゴリーを開いたときは、結果を捨てる。** 番号（`openCount`）で、古い応答を見分ける（詳細モーダルと同じ作り）。読み込めなかったときは、編集させない（`loaded`）。空のテンプレートで、上書き保存してしまう事故を防ぐ

## やってみよう
1. HP のテンプレートを開き、項目の名前を直して、保存する。もう一度開いて、直った内容か確かめる
2. 変更したまま、枠の外を押す。閉じないことを確かめる
3. 依頼を開いて「テンプレートを入れる」を押し、直したテンプレートの内容が入ることを確かめる
4. `templateEdit.test.ts` を開き、`isTemplateChanged` が、前後の空白だけの違いを、変更と見なさないことを確かめる
