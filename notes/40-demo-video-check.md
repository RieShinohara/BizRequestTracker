# 2本目の動画（カテゴリー管理・テンプレート編集）の確認と変換

Issue #133。カテゴリー管理とテンプレート編集の操作を、撮影して、README に足した。撮影したのは、AWS にデプロイした画面。**公開する前の確認で、映ってはいけないものを見つけて、直してもらった**。

## 学んだこと
- **入力変換（予測変換）の候補が、映り込む。** 日本語を打つと、Windows の入力システムが、**自分の入力履歴**から、候補を出す（「選択：Tab」「先頭を確定：Shift+Enter」と書いてある、小さな窓）。履歴には、**実在の会社名や、実際の仕事の言葉**が入っていることがある。画面を録画すると、そのまま映る。公開するなら、**編集でぼかす**か、**文字を貼り付けて入力する**（貼り付けなら、候補が出ない）か、入力変換の予測を切ってから、撮る
- **確認は、フレームを抜き出して、見る。** `fps=1`（1秒に1枚）で、たくさんのフレームを、1枚の画像に並べて（`tile=4x3`）、まとめて見た。**怪しい所だけ、拡大して、細かく見る**（ぼかしが、効いているか）。4秒おきの粗い確認で見つけた問題が、1秒おきの確認で、直ったと分かる
- **「音声なし」のつもりでも、音声トラックが入っていることがある。** 無音（-91 dB）でも、トラックがあるだけで、約4MB 増える（18MB → 14MB）。**映像は、再エンコードせず**（`-c:v copy`）、音声だけを外した（`-an`）ので、画質は、変わらない
- **ファイルに名前を付けて、直した版を残す。** `-rev01` のように、版を付けて、元のファイルを上書きしない。やり直しが、できる
- **使い捨ての Docker で、ffmpeg を動かす。** PC には入れない。静的にビルドされたイメージ（`mwader/static-ffmpeg`）の中の道具は、`/ffmpeg` と `/ffprobe`。`ffprobe` を動かすときは、`--entrypoint /ffprobe` と書く。Windows のパスを、Git Bash から渡すとき、`MSYS_NO_PATHCONV=1` を付けないと、パスが勝手に変換されて、失敗する
- **GIF は、動画の一部を切り出して、作る。** `-ss 5 -t 20`（5秒から20秒間）、幅 800px、12fps、パレット最適化（`palettegen` と `paletteuse`）で、**1.4MB**。1本目の GIF と同じくらい

## 提出前に分かったこと：リポジトリの MP4 は、GitHub の画面で再生できない（Issue #137）
- **ファイルの画面で、大きな動画は、表示されない。** 「このサイズのファイルは表示できません」と出て、「View raw」を押すと、ダウンロードになる。配信側が、動画を「ただのデータ（`application/octet-stream`）」として返すため、ブラウザが再生しない。**壊れているわけではない**
- **README の中で再生するには、GitHub の「添付」を使う。** PR や Issue のコメント欄に、動画をドラッグ＆ドロップすると、`https://github.com/user-attachments/assets/…` の URL ができる（コメントは、送信しなくてよい）。その URL を、README に**1行だけで**貼ると、その場で再生される
- **無料のアカウントは、1ファイル 10MB 以下**（合計ではなく、1本ずつ）。24MB と 14MB の動画を、**毎秒30枚→15枚にして、ビットレートを下げる 2パスの変換**で、8.9MB と 7.4MB にした。画面録画は動きが少ないので、画質はほぼ変わらない。**上限ぎりぎり（9.98MB）は避けて、1MB ほど余裕を持たせた**
- **「確かめたつもり」を、実際の画面で確かめる。** ファイルが取れる（HTTP 200）ことと、ブラウザで再生できることは、別。画面で見て、初めて分かった

2. 自分で動画を撮るとき、**撮る前に**、入力変換の予測を切るには、どうするとよいか、調べてみる
