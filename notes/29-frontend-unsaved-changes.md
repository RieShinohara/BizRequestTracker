# 画面：変更中にうっかり閉じない（詳細モーダル）

品質チェックの F2（[docs/quality-review.md](../docs/quality-review.md)）への対応。詳細モーダルは、枠の外を押す・Esc キーで、確認なしに閉じ、編集中の内容が消えた（ユーザーが画面で確認した）。

## 直したこと
| 状況 | 前 | 後 |
|---|---|---|
| 変更なしで、外側・Esc | 閉じる | 閉じる（同じ） |
| 変更ありで、外側・Esc | **閉じて、入力が消える** | 閉じない |
| 変更ありの「閉じる」ボタン | 「閉じる」 | 赤い「変更を捨てて閉じる」＋「保存していない変更があります」 |

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/requestForm.ts` の `isFormChanged` | 開いたときの入力内容と、今の内容を比べて、変わっているかを返す |
| `frontend/src/requestForm.test.ts` | 上のテスト（5件） |
| `frontend/src/components/RequestDialog.vue` | 開いたときの写し（`original`）を持ち、`dirty`（変更あり）で、`persistent` と、閉じるボタンの表示を切り替える |

## 学んだこと
- **「変更があるか」は、「開いたときの写し」と比べて決める。** 入力欄の中身（`form`）は、画面で直すたびに書き換わる。そのため、開いたときに、**同じ内容の別の写し**（`original`）を作っておく（`detailToForm` を2回呼ぶ。別々のオブジェクトになる）。1つのオブジェクトを2つの名前で持つだけだと、片方を直すと、もう片方も変わってしまい、比べられない
- **「元に戻した」ときは、変更なしに戻る。** 1文字変えて、元に戻すと、「保存していない変更があります」は、消える。「一度でも触ったか」ではなく、「今の内容が、元と同じか」で決めているため。前後の空白だけの違いは、変更と見なさない
- **見張る範囲は、画面に出ているものすべて。** 入力欄だけでなく、チェックリストのチェックの付け外し・順番、「項目を足す」の書きかけの文字も、変更に数える。見落とすと、「そこだけ消えてしまう」穴が残る
- **プログラムから閉じるときは、`persistent` は邪魔をしない。** `persistent` が止めるのは、「枠の外を押す・Esc」という、ユーザーの操作だけ。「保存」や「アーカイブ」の成功で、親が閉じるときは、そのまま閉じる
- **同じ考えを、2つの画面にそろえた。** テンプレート編集（`TemplateDialog.vue`）も、同じ作り（変更があると、閉じない／「変更を捨てて閉じる」）。使う人は、どの画面でも、同じ動きを期待できる。ただし、同じ処理が2か所にあるので、増えるときは、共通の部品にまとめることを考える

## やってみよう
1. 依頼を開き、タイトルを1文字変えて、枠の外を押す。閉じないことを確かめる。元に戻すと、閉じられるようになることも確かめる
2. `requestForm.test.ts` の `isFormChanged` のテストを開き、「チェックの付け外し」「順番の入れ替え」が、変更になることを確かめる
