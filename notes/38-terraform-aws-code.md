# Terraform：AWS の構成のコードを書く（デプロイの準備 1/3）

Issue #129。AWS（EC2 と RDS）にデプロイするための、Terraform のコードを書いた。**AWS には、何も作っていない**（作るのは、別の日に、ユーザーが承認してから）。構成は、1本目（TaskManagement）を基にしている。構成の説明は、[docs/infrastructure.md](../docs/infrastructure.md)、使い方は、[terraform/README.md](../terraform/README.md)。

## 1本目から、変えたところ
| 項目 | 1本目 | 今回 |
|---|---|---|
| データベース | RDS PostgreSQL（5432番） | RDS **MySQL 8.4**（3306番）。版は、AWS が既定にしている 8.4.11 |
| バックエンド | Java（jar）、8080番 | **Python（FastAPI）、uvicorn、8000番** |
| EC2 に入れる道具 | nginx、Java、Node.js、psql | **nginx と uv** だけ（Java も Node.js も要らない。画面は、手元でビルドする） |
| RDS を作るか | いつも作る | **`create_database` のスイッチ**で、作る・作らないを切り替える |

## 学んだこと
- **前にやった構成は、そのまま、土台にできる。** 1本目の `.tf` を読み、変える所（DB の種類、ポート、道具）だけを直した。**変えた理由を、コメントに書く**と、あとで読む人（自分）が、迷わない
- **スイッチ（変数）で、段階ごとに作る。** `count = var.create_database ? 1 : 0` と書くと、変数が `false` のときは、その物を作らない。`true` に書き換えて `apply` すると、**足りない分（RDS）だけが、足される**（Terraform は、今ある物と、書いてある物の、差分だけを実行する）。確認しながら、少しずつ作るのに、便利。スイッチで、作る・作らないが変わる物を、別の場所から使うときは、`aws_db_instance.main[0]`（0 番目）のように書く。出力では、`var.create_database ? … : null`
- **点検の道具は、「書いてある通りに」調べる。** trivy は、スイッチが `false` のとき、RDS を調べない（作らないので）。**`true` にしたときの指摘を、見落とさない**よう、ダミーの値を書いた一時ファイルを `--tf-vars` で渡して、調べた。結果：6件。どれも、1本目と同じ、「意図した設定」（出口の全部許可、RDS のバックアップなし・IAM 認証なし・削除の保護なし・性能分析なし、VPC のフローログなし）。**足すだけで、点検は通ってしまう**ので、1つずつ、「本当に、対応しなくてよいか」を考えて、理由を書いて、`.trivyignore` に残した
- **`plan` は、「作る前の、答え合わせ」。** 書いたコードで、何が作られるかを、確かめた：スイッチ切で 13個、入で 17個。**入口が、自分の IP の `/32` と、EC2 のグループだけ**になっていること、RDS が、公開なし・Multi-AZ なし・バックアップなしであることを、予告の中身で確認した。**自分の IP と、パスワードは、ダミーの値を `-var` で渡した**（ファイルに書かない）。出力を、**12桁の数字**（アカウント ID の疑い）で検索して、混ざっていないことを確かめてから、読んだ。**公開鍵の中身は、出力に出る**ので、見せない
- **値は、AWS に問い合わせて決める。** MySQL 8.4 の版を、推測で書かず、AWS に聞いた（読み取りだけ）：使える版は 8.4.8〜8.4.13。**既定の版は 8.4.11**。最新の 8.4.13 ではなく、既定の版を選んだ（出たばかりの版を避ける、という、これまでの方針と同じ）。`db.t4g.micro` で、その版が選べることも、確かめた。**問い合わせの書き方でつまずいた**：`8.4` を、そのまま書くと、数字として解釈されて、エラーになる。文字として、引用符で囲む
- **入力の制限は、サービスごとに違う。** MySQL（RDS）は、管理者の名前が **16 文字まで**、パスワードは **41 文字まで**、使えない文字は `/ @ ' "` と空白。1本目（PostgreSQL）の、「12〜64 文字」を、そのまま使うと、MySQL で、失敗する。変数の検証に、上限を書いた（エラーを、`apply` の前に、気づける）
- **動かしている間に、勝手に変わらないように。** RDS の `auto_minor_version_upgrade = false`（版が、勝手に上がらない）。EC2 に入れる `uv` は、**手元と同じ版（0.13.7）の URL**から取る（あとで、中身が変わらない）
- **DB の文字コードは、既定のままで、よい。** RDS の MySQL 8.4 は、既定で、`utf8mb4` を使う。手元の Docker（`docker-compose.yml`）と同じ。確認は、当日、DB につないで行う
- **作る前に、1本目の後片づけを、確認した。** 読み取りだけで、EC2・RDS・NAT・Elastic IP・EBS・スナップショット・自作の VPC・セキュリティグループ・キーペアが、すべて **0 件**であることを、数で確かめた（アカウント ID や IP は、出さない）。**費用がかかる物が、残っていない**ことを、先に、確認する

## やってみよう
1. `terraform/variables.tf` を開き、`create_database` を探す。`rds.tf` で、どこに使われているか見る
2. `terraform/` で `terraform validate` を実行する（`terraform init -backend=false` のあとで。AWS には、何も作らない）
3. `.trivyignore` の6件について、「なぜ、対応しなくてよいか」を、自分の言葉で、説明してみる
