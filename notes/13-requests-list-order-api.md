# 依頼の一覧と、手動の並びの保存の API

## 作ったもの
| 窓口 | 内容 |
|---|---|
| `GET /api/requests` | 依頼の一覧。検索・絞り込み・並び替えを、サーバー側で行う |
| `PUT /api/requests/order` | 手動の並びの保存（ドラッグ＆ドロップの結果を保存する） |

場所は `backend/app/routers/requests.py`。テストは `backend/tests/test_requests_list_api.py`（33件）。仕様は [docs/api-design.md](../docs/api-design.md) の「3.1」「3.6」。これで、API は全17本が完成した。

## 一覧の条件
条件は、URL の後ろに `?q=...&qms=true` のように付ける。すべて省略できて、組み合わせられる。

| 条件 | 意味 |
|---|---|
| `q` | 検索。タイトル・詳細・依頼者の名前・確認先に含まれるもの |
| `qms` | `true` のときだけ、QMS の依頼に絞る |
| `category_id` | そのカテゴリーだけ |
| `status` | そのステータスだけ |
| `include_archived` | `true` なら、アーカイブ中も含める |
| `sort` | `priority`・`due_on`・`status`。省略すると手動の並び |

## 学んだこと
- **検索・絞り込み・並び替えは、サーバーで行う**：画面に全件を渡して、画面で絞ることもできる。でも、件数が増えると重くなり、検索の決まりが画面とサーバーに2つできてしまう。決めごとを1か所（サーバー）に置いた
- **条件は、足していく**：`select(Request)` に、条件があるものだけ `.where(...)` を足していく。条件が省略されたら、何も足さない。組み合わせ（`AND`）は、自然にできる
- **文字の順番は、五十音順にしない**：優先度の「急ぎ→高→中→低」は、五十音順でも文字コード順でもない。`CASE`（値を番号に直す）を使って、決まった順番に並べる
- **同じ値どうしは、手動の並びのまま**：`ORDER BY 優先度の番号, sort_order` と、2段で並べる。優先度が同じ依頼は、`sort_order`（手動の並び）で決まる
- **「見せ方」と「並びの保存」は別**：`sort=priority` で並べ替えても、`sort_order` は書き換えない。手動の並びは、`PUT /order` で保存したときだけ変わる
- **検索の `%` と `_`**：SQL の `LIKE` では、`%`（なんでも）と `_`（1文字）が特別な文字になる。「100%」を探したのに、「100円」まで出てしまう。`%` と `_` の前に `\` を付けて、ふつうの文字にする（エスケープ）
- **検索は、大文字・小文字を区別しない**：MySQL の標準の設定（`utf8mb4_0900_ai_ci` の `ci`＝case insensitive）のおかげ。`website` で `Website` が見つかる
- **並びの保存は、「全部そろっているときだけ」**：`ids` は、アーカイブ中を除く全依頼の番号を並べたもの。別の画面で依頼が増えた・減ったなどで、過不足があると、何も変えずに 409（「一覧が古くなっています」）。古い画面の並びで、新しい依頼の位置を壊さないため
- **アーカイブ中は、並びの保存の対象外**：アーカイブ中の依頼の番号は、書き換えない
- **N+1 問題を避ける**：一覧で、依頼ごとに、依頼者・カテゴリー・チェックリストを1件ずつ DB に聞くと、100件なら300回の問い合わせになる（N+1問題）。`joinedload`（依頼者・カテゴリーを、同じ問い合わせで一緒に取る）と、`selectinload`（チェックリストを、まとめて1回で取る）で、問い合わせを数回に減らした

## 要件にない、私（Claude Code）が決めた点
- 検索の文字は、前後の空白を取り除く。空（空白だけ）なら、検索しない
- `qms=false` は、絞らない（QMS でない依頼だけに絞る、という意味にはしない）。設計書が「`true` なら QMS の依頼だけ」としか書いていないため
- 決められた値以外の `status`・`sort` は 422
- 並びの保存で `ids` が重複していたときも、過不足と同じく 409

## つまずいたこと
- **テストの期待値の書き間違い**：文字を並べ替えた結果が、書いた順と違った。API の不具合ではなかった。順番が目的でないテストは、`set`（集まり）で比べる
