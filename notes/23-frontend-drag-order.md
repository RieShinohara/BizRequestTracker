# 画面：ドラッグでの並び替え（手動の並びの保存）

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/package.json` | `vue-draggable-plus`（0.6.1）を追加 |
| `frontend/src/order.ts` | 並びの計算（普通の関数）。`moveItem`（動かした後の配列）、`orderIds`（保存で送る番号。アーカイブ中を除く）、`dragDisabledReason`（ドラッグできない理由） |
| `frontend/src/components/RequestTable.vue` | 取っ手（`.drag-handle`）でドラッグ。動かしたら、新しい並びを親に伝える（`reorder`）。ドラッグできないときは、取っ手を薄くして、理由をマウスを乗せたときに出す |
| `frontend/src/api.ts` | `saveOrder`（`PUT /api/requests/order`） |
| `frontend/src/App.vue` | 並びを保存して、一覧を取り直す。保存中は、ドラッグできない |

## 学んだこと
- **ドラッグできるのは、手動の並びのときだけ**：優先度順などのときに動かしても、「全体の手動の並び」のどこに入れたのかが決まらない。検索・絞り込み中も同じ（一部しか見えていないため）。なので、取っ手を使えなくして、理由を出す。ただし、「アーカイブも表示」だけの場合は、並びの保存に影響しない（保存で送るのは、アーカイブ中を除いた番号だけ）ので、ドラッグできる
- **並びの保存は、「全部の番号」を送る**：API は、「アーカイブ中を除く全依頼の番号を、並べたもの」を受け取る。1件だけを動かした、という情報ではない。だから、画面は、動かしたあとの一覧の並び全体を計算して送る（`orderIds`）
- **画面に先に反映して、保存する（楽観的な更新）**：ドラッグした瞬間に、画面の並びを変える。保存の返事を待つと、離した行が元の位置に戻って、また動く、という見た目になるため。保存できなかったときは、一覧を取り直して、元の並びに戻す
- **保存のあとは、成功しても失敗しても、取り直す**：画面を API の実際の並びに合わせる。別の画面で依頼が増減していて 409 になったときも、これで正しい一覧に戻る
- **保存中は、ドラッグできなくする**：保存が終わる前に、続けて動かすと、古い並びを基準に計算してしまう。保存中は、ドラッグを止める
- **部品の「元の配列」を、自分では書き換えない**：ドラッグの部品は、渡した配列（`list`）を自分で並べ替える。親から届いた一覧（`props.rows`）は、書き換えてはいけない（Vue のルール）ので、表の中に、コピーの配列（`list`）を持って、部品に渡した。親から新しい一覧が届いたら、コピーを入れ替える
- **動かした位置は、部品の通知（`oldDraggableIndex`、`newDraggableIndex`）から、自分で計算する**：部品が内部で並べ替える順番や仕組みに頼らず、「ドラッグの前の一覧」と「動かした位置」から、新しい並びを計算した（`moveItem`）。テストもしやすい
- **`draggable: '.row'`**：「依頼がありません」の行は、ドラッグの対象にしない。対象の行を、クラスで絞る
- **途中の状態で、エラーが出ることがある**：スクリプトとテンプレートを別々に編集すると、その間の、辻褄が合わない状態を、開発用サーバーが読み込んで、一時的にエラーを出す（`el must be an HTMLElement`）。直後の更新で消えた

## 要件にない、私（Claude Code）が決めた点
- 「アーカイブも表示」がオンのときも、ドラッグできる（アーカイブ中の依頼の並びは、API が変えないため）。アーカイブ中の行を動かしたときも、アーカイブ中を除いた並びだけを送る
- ドラッグできないときの理由は、取っ手にマウスを乗せたときに出す（画面の別の場所には、出さない）
- 保存に失敗したときは、お知らせを出して、一覧を取り直す

## 確認が必要なこと
- ブラウザで、見た目と動きを確認する（私は、ブラウザを操作できない）。特に、ドラッグの感触（動く・離す・保存）
- 本物の API で、並びの保存（204）、不足がある並びが 409 になること、失敗しても並びが変わらないこと、元に戻せることを確認した
