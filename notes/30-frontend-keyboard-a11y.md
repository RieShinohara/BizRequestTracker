# 画面：キーボードで操作できる・読み上げソフトに伝える（一覧）

品質チェックの F3（[docs/quality-review.md](../docs/quality-review.md)）への対応。一覧の依頼を開く操作が、行のクリックだけで、Tab キーでは届かず、Enter でも開けなかった（ユーザーが画面で確認した）。

## 直したこと
| 状況 | 前 | 後 |
|---|---|---|
| Tab で、依頼のタイトルに止まる | 止まらない | 止まる（枠が出る）。Enter で、詳細が開く |
| モーダルを閉じたあと、Tab を押す | ページの先頭（Chrome のタブ）からやり直し | 開いたボタンの次へ進む |
| ドラッグの取っ手 | 読み上げソフトに、何か伝わらない | 説明を読み上げる（ドラッグできないときは、その理由） |
| 期限の色（赤・オレンジ） | 色だけ | 「（期限切れ）」「（3営業日以内）」も読み上げる |
| QMS のチェックの印 | 絵だけ | 「QMS チェックあり」も読み上げる |

見た目は、ほぼ変わっていない（文字は、ふつうのまま。枠は、Tab で止まったときだけ）。ドラッグのキーボード対応は、作らない（判断済み。使う人は1人。複数人で使うときに、見直す）。

## 作ったもの
| 場所 | 中身 |
|---|---|
| `frontend/src/components/RequestTable.vue` | タイトルのボタン、読み上げ用の文字（`.visually-hidden`） |
| `frontend/src/display.ts` の `dueLevelLabel` | 期限の色を、文字にする（テストつき） |
| `frontend/src/App.vue` | 開いたボタンを覚えて、閉じたあとに戻す（`rememberOpener`・`restoreFocus`） |
| `frontend/src/styles.css` | 戻したボタンの枠（`.restored-focus`） |

## 学んだこと
- **行（`<tr>`）のクリックだけでは、キーボードの人は開けない。** マウスの操作（クリック）に結び付けた部品は、Tab で止まらず、Enter も効かない。**本物のボタン（`<button>`）を使う**のが、いちばん確実。ボタンは、Tab で止まり、Enter・スペースで押せ、読み上げソフトにも「ボタン」と伝わる。`div` や `tr` に、クリックの処理だけを付けても、同じ動きにはならない
- **見た目は、ふつうの文字のまま、中身をボタンにできる。** 背景・枠・余白を消し、文字の色と大きさを、親から引き継ぐ（`font: inherit; color: inherit`）。枠は、`:focus-visible`（キーボードで止まったときだけ）に出す
- **行のクリックとボタンのクリックが、二重に動かないようにする。** ボタンのクリックは、親の行にも伝わる（バブリング）。`@click.stop` で、伝わるのを止める。行のクリックも残すので、マウスの人には、これまでどおり
- **モーダルを閉じたら、開いたボタンに、Tab の位置を戻す。** モーダルを開くと、Tab の位置はモーダルの中に移る。閉じたとき、元に戻さないと、**ページの先頭からやり直し**になる。今回は、Vuetify の部品が、「開いたボタン」を知らない作り（状態で開いている）なので、**開く前に、いま Tab の位置にあるボタンを覚えておき、閉じ終わったら戻す**。閉じ終わりは、`v-dialog` の `after-leave` で分かる
- **「戻っている」のに「枠が出ない」ことがある。** マウスで「閉じる」を押すと、ブラウザは「キーボードで来た」とは見なさず、戻した位置に、枠を出さない。ユーザーの確認では、枠が出ないのに、次の Tab が正しく進んだ（＝位置は戻っていた）。**見えないことと、起きていないことは、別**。Tab で来ていた人には枠が見えたほうが親切なので、開いたとき、そのボタンがキーボードで止まっていたか（`:focus-visible` に合うか）を覚えておき、そのときだけ枠を出す。`focus({ focusVisible })` は、「枠を出す・出さない」を指定する新しい書き方で、対応していないブラウザでは、無視される
- **読み上げソフト向けの文字は、画面から隠して、読み上げだけに残す。** `display: none` や `hidden` では、読み上げソフトからも消える。**1px に縮めて、切り取る**（`.visually-hidden`）と、見えないが、読まれる。色だけで伝えていた情報（期限の色）は、**文字でも伝える**。色の見分けがつきにくい人や、読み上げソフトの人に、同じ情報が届く
- **実際の聞こえ方は、人が確かめるしかない。** テストできるのは、文字が入っていること。Windows のナレーター（Win + Ctrl + Enter）で、聞こえ方を確かめられる（今回は未確認）

## やってみよう
1. 画面を開き、Tab だけで、タイトルまで進む。Enter で開き、Esc で閉じる。枠が戻ることを確かめる
2. 同じ操作を、マウスで「閉じる」を押す形でも行う。枠が出なくても、次の Tab で、次のステータスに進むことを確かめる
3. `RequestTable.vue` を開き、タイトルの `<button>` と、`.visually-hidden` を探す
