# AWS へのデプロイの記録（デプロイの準備 3/3）

Issue #135。2026-11-10 の夜（22:00〜23:35）に、AWS へ、実際にデプロイした。入れ物を作り、アプリを置き、動作確認と録画をして、最後に全部消した。この記録は、**やったことの順番**と、**学んだこと**。

## いちばん大事な整理：「Terraform」と「デプロイ」は、別の作業
お店にたとえると、分かりやすい。

| たとえ | 実際 | 道具 |
|---|---|---|
| 店舗を借りて、内装・備品・鍵を整える | VPC・サブネット・セキュリティグループ・EC2・RDS を作る | **Terraform** |
| 商品を運び込んで、開店する | アプリを置いて、動かす（これが**デプロイ**） | scp・ssh（自分の PowerShell） |
| 閉店して、店舗を返す | 作った物を全部消す | **Terraform（`destroy`）** |

- **Terraform で作った物は、「起動する」物ではない。** 作れば、そこにある設備（ネットワークの区画、通行のルール、サーバー、データの倉庫）
- **デプロイは、アプリを動く場所に置いて、お客さん（ブラウザ）が使える状態にすること。** 起動するのは、アプリ（と、それを支える nginx と systemd）
- 最初は、「Terraform でアプリも置いた」と思っていた。**違いが分かると、どこで何が起きているか、見通せるようになる**

## やったことの順番
1. **段階①（Terraform）**：ネットワークと EC2（13個）を作る → SSH とブラウザで確認（nginx の標準ページが出る）
2. **段階②（Terraform）**：RDS（MySQL 8.4。外からは入れない場所）を足す（4個追加。作成に約5分）
3. **段階③（デプロイ）**：画面をビルド（Vue → ブラウザ向けのファイルに変換。Python は変換が要らない）→ 1つのファイル（`bundle.tgz`）にまとめる → scp で EC2 に送る → EC2 の中で、部品を入れる（`uv sync`）→ `.env` を作る → 表を作る（`alembic upgrade head`）→ systemd と nginx で動かす
4. **確認**：`/health`、`/api/summary`、`/docs` が 404 になること、8000番が外から見えないこと、ブラウザで一覧・カテゴリー7つ・依頼の保存と再読み込み
5. **録画**
6. **`terraform destroy`**（17個。RDS の削除は約2分）。**残っていないことを、数で確認した**（EC2・RDS・スナップショット・EBS・EIP・NAT・VPC・サブネット・IGW・SG・キーペア。すべて 0 件）

各段階で、**`plan` を読んでから、承認して `apply`** した。段階に分けたので、問題が起きても、どこで起きたか分かる。

## 学んだこと
- **段階に分けて作る**と、確認しながら進められる。EC2 だけの段階で、SSH とブラウザを確かめてから、費用の大きい RDS を足した
- **お金がかかるのは、動かしている間だけ。** 録画が終わったら、すぐ `destroy` した。消したあとは、「消したはず」ではなく、**数で確認する**（0 件）
- **SSH の鍵に、パスフレーズをかけていると、AI は代わりにログインできない。** 鍵とパスフレーズは、本人だけが持つ物なので、これは良い仕組み。ssh・scp は、本人の PowerShell で行った。**パスフレーズは、チャットに書かない**
- **送る物は、1つのファイルにまとめる**と、パスフレーズの入力が1回で済む
- **道具の癖**：Git Bash の `tar` は、`C:` を「別のサーバー」と誤解する（`--force-local` が要る）。PowerShell では、`$ip = terraform -chdir=terraform output -raw public_ip` で、値を変数に入れられる
- **秘密のファイルは、名前で守られている。** `.gitignore` が除外するのは `*.tfplan`。`-out=tfplan`（拡張子なし）と書いたら、除外されず、コミットされかけた。**名前の決まりを、守る**
- **録画では、映り込みに気をつける**（IP アドレス、入力変換の候補。ノート 40）
