# 04 REST API の早見表

確認テストの復習用。API 設計（[03-api-design.md](03-api-design.md)）で出てきた REST の基本を、1ページにまとめる。例は、このアプリの [API 設計](../docs/api-design.md) から。

## 1. REST とは
- 画面とバックエンドのやり取り（API）の、**作り方の約束**
- 考え方：**「もの」を URL で表し、「やりたいこと」をメソッドで表す**
- レストランにたとえると：URL ＝ 何について（メニュー、注文）、メソッド ＝ どうしたい（見せて、追加して、変えて、取り消して）

## 2. 操作とメソッド
| やりたいこと | メソッド | 例 | 補足 |
|---|---|---|---|
| 取得する | `GET` | `GET /api/requests` | 見るだけ。データは変わらない |
| 追加する | `POST` | `POST /api/requests` | 新しいものを作る。成功は `201` |
| 一部だけ更新する | `PATCH` | `PATCH /api/requests/9` | **送った項目だけ**変わる |
| 丸ごと入れ替える | `PUT` | `PUT /api/categories/4/template-items` | 送った内容で**全部置き換える** |
| 削除する | `DELETE` | `DELETE /api/requests/9` | 成功は `204`（中身なし） |

- この4つ（作る、見る、変える、消す）は、**CRUD**（Create・Read・Update・Delete）とも呼ぶ
- `PUT` と `PATCH` の違い：`PUT` は全部を送って置き換える、`PATCH` は変えたい所だけ送る。「ステータスだけ変えたい」なら `PATCH`（他の項目を古い値で上書きしないため）
- 同じ `PUT` を何度送っても、結果は同じになる（これを**冪等**という）。`POST` は、送るたびに増える

## 3. URL の決まり
- **名詞**（もの）で書く。動詞は入れない：`/api/requests`（○）、`/api/getRequests`（×）
- **複数形**で、一覧を表す：`/api/requests`
- **番号**を付けると、1件を表す：`/api/requests/9`
- **入れ子**で、持ち物を表す：`/api/categories/4/template-items`（カテゴリー 4 のテンプレート項目）
- **絞り込みや並び替え**は、`?` の後ろに条件を付ける：`/api/requests?q=通関&qms=true&sort=due_on`（複数は `&` でつなぐ）。窓口は増やさない

## 4. ステータスコード（返事の番号）
| 番号 | 意味 | このアプリでの例 |
|---|---|---|
| `200` | 成功 | 一覧や1件の取得、更新 |
| `201` | 作成できた | 依頼の追加 |
| `204` | 成功。返す中身はない | 依頼の削除 |
| `400` | リクエストの形が間違っている | （FastAPI では、多くが 422 になる） |
| `404` | 見つからない | 存在しない依頼の番号 |
| `409` | 今の状態ではできない（競合） | 同じ名前の登録、使用中のカテゴリーの削除、アーカイブしていない依頼の削除 |
| `422` | 入力が正しくない | タイトルが空、ステータスが5つのどれでもない |
| `500` | サーバーの中の不具合 | プログラムの誤り |

- 番号の**最初の数字**で、大まかに分かる：`2xx` ＝ 成功、`4xx` ＝ 送った側（画面）の問題、`5xx` ＝ サーバー側の問題
- 1本目（Spring Boot）では入力の間違いを `400` で返すことが多い。今回（FastAPI）は、標準で `422` を返す。**番号が違っても、「入力が正しくない」という意味は同じ**

## 5. 送るデータの形（JSON）
- やり取りは **JSON**（`{"項目名": 値}` の形）
- 依頼の追加の例：
```json
{"title": "（架空）通関書類の作成", "requester_id": 2, "category_id": 4, "due_on": "2026-11-10"}
```
- 一部だけの更新（ステータスだけ）：`{"status": "作業中"}`
- 失敗したときの理由：`{"detail": "アーカイブ中の依頼だけ削除できます"}`
