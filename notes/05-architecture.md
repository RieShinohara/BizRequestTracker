# 05 画面とバックエンドの構成

「画面とバックエンドを別々に作る」とは、どういうことか。質問から整理した記録。

## 1. 「別々」には、2つの意味がある
| 話 | 問い | 今回 |
|---|---|---|
| **構成の話** | プログラムが、画面とバックエンドで**分かれているか** | 分かれている（Vue ＋ FastAPI） |
| **進め方の話** | **人**が、画面担当とバックエンド担当に分かれているか | 分かれていない（ユーザーと Claude Code で、両方を作る） |

この2つは別の話。構成が分かれていても、1人（または1チーム）で両方を作れる。

## 2. 構成の比較
| | 分けた構成（今回、1本目） | 一体型（Next.js など） |
|---|---|---|
| 作り | 画面とバックエンドが、**別のプログラム** | 1つのプログラムに、画面とサーバー側の処理が**両方**ある |
| つなぎ方 | **API**（窓口）で話す | 同じプログラムの中で呼び出す |
| 言語 | 別々にできる（今回：TypeScript と Python） | 全部 TypeScript にできる |
| 今回の例 | Vue 3 ＋ FastAPI。1本目は React ＋ Spring Boot | |
| 向いている場面 | バックエンドを別の言語で作りたい。画面を何種類も使う | 1つの Web サイトを、少人数で手早く作る |

- 1本目（Java + Spring Boot ＋ TypeScript + React）も、**分けた構成**だった。今回は、両方の言語とフレームワークを変えて、同じ構成をたどる
- 分けた構成では、2つをつなぐ**約束（API）**が大事。だから、実装の前に API 設計書を書いた（[03-api-design.md](03-api-design.md)）

## 3. 進め方の変化
- 昔：バックエンド担当とフロントエンド担当が別の人。API の約束を先に決めないと、お互いに作れなかった
- 今：AI を使うと、**1人で両方を作りやすい**。講義で聞いた「同時に作っている」は、この意味
- ただし、今回も**順番は「API → 画面」**で、Issue と PR は別にしている。約束（API）を先に決めると、画面を作るときに迷わない。1人で作る場合でも役に立つ

## 4. Vue・React・Next.js の位置づけ（一般的な知識）
| 名前 | 何か | 補足 |
|---|---|---|
| React | 画面の部品を作る道具（ライブラリ） | 使う人が多い。1本目で使った |
| Vue | React と同じ役割の道具 | HTML に近い書き方。部品集 Vuetify がある。今回使う |
| Next.js | React の上に作られた、大きな枠組み（フレームワーク） | 画面の切り替えや、サーバー側で画面を作る機能が入っている |
| Nuxt | Next.js の、Vue 版にあたる枠組み | 今回は使わない |

- Vue と React は、**役割が同じ**。どちらも、画面を部品に分けて作る
- 今回は、画面とバックエンドを別に作るので、Next.js や Nuxt の「サーバー側で画面を作る」強みは、あまり使わない
- **Vue を選んだ理由**（ユーザーの記憶による。当時の記録は残っていない）：
  1. 課題の条件が「React を変える」ことだった
  2. 先生が **Material UI**（Google の Material Design の部品集）を使ったと聞いて、同じ種類の部品集が Vue にもあると知った。それが **Vuetify**（Vue 版の Material Design の部品集。React の Material UI にあたる）
  3. 表、ボタン、モーダル、入力欄が最初から用意されていて、一覧と詳細モーダルの画面に合っていた

## 5. 学んだこと
- 「別々」という言葉は、**何が別々か**（プログラムか、人か）を分けて考える
- 技術を選ぶときは、「何を選んだか」だけでなく、**なぜか**を残す。あとから聞かれたときに、答えられる
