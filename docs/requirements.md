# 要件定義書：社内業務依頼管理＆作業テンプレートアプリ

この文書は、要件定義の全体像をまとめた入口である。詳細は、内容ごとに別のドキュメントに分けている。
ヒアリングで決まったことをまとめている（2026-11-03 時点＋プロトタイプで決めたこと）。仕様を変えるときは、ユーザーに確認してから、該当の文書を更新する。

## 1. 目的と使う人
- 他部署からの制作依頼（通関書類、HP、取扱説明書、動画、オフィス移転など）を、1か所で管理する
- 使う人は1人（業務部の担当者）。ログインは、今回は作らない
- 画面は、依頼の**表（一覧）**と、**詳細モーダル**（一覧から開くウィンドウ）で作る。参考：Dribbble の Aivia チケット画面
- サンプルデータは、すべて**架空**（公開リポジトリのため）

## 3. 範囲の概要
- 依頼を、表（一覧）で管理する。ステータスは「未着手・作業中・確認待ち・完了」と「ペンディング」
- 一覧から、ステータスの変更、検索、絞り込み（QMS・カテゴリー・ステータス）、並び替え（手動・優先度・期限日）ができる。手動の並びは、ドラッグ＆ドロップで変える
- 期限が近い・過ぎた依頼を、色で目立たせる（営業日で数える）
- 依頼を押すと、詳細モーダルが開く。業務カテゴリーごとの作業テンプレートをワンクリックで入れて、チェックリストとして使える
- 依頼は消さずに、アーカイブして残す。完全に削除できるのは、アーカイブ中の依頼だけ
- 使う人は1人で、ログインは作らない

## 4. 未決（これから決める）
- 引っ越し（オフィス移転）の作業項目（仮のまま。経験したら見直す）
- 確認先の最初の候補（依頼者、薬事部、開発部、営業部、工場）を、どこに置くか。案：設定ファイルに書く（会社の休みと同じ形。Claude のおすすめ）／最初は空で、使った文字だけが候補に出る。API を作るときに決める
