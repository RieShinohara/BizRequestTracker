## 3. 良かった点
- **API の守りが堅い**：入力の検査（空・長さ・許される値）を、サーバー側の入口（Pydantic）で行っている。画面の検査に頼らない。ステータスと優先度は `Literal` で、決まった値以外を弾く
- **エラーの返し方がそろっている**：404・409・422 を、理由つき（日本語の `detail`）で返し、同じ名前の重複は、DB の制約（`IntegrityError`）で受け止めている
- **データの守り**：外部キー（`RESTRICT`／`CASCADE`）で、カテゴリーを使っている間は消せない。依頼を消すとチェックリストも一緒に消える。LIKE 検索の特別な文字（`%`・`_`）を無効にしている。`DELETE` は、アーカイブ中だけ
- **一覧の取得が効率的**：依頼者・カテゴリーを `joinedload`、チェックリストを `selectinload` で、まとめて取っている（1件ずつ取る N+1 を避けている）
- **日付の考え方**：期限の色は日本時間で決め、テストで日付を固定できる作りになっている
- **画面の競合への配慮**：古い応答を捨てる番号（一覧、詳細モーダル）、保存後の取り直しで画面を実際の状態に合わせる、日本語変換中の Enter を無視する、など
- **画面の作りの分け方**：決まりごとを部品から切り離し（`requestForm.ts`、`order.ts` など）、関数として 99 件のテストで守っている。`v-html` は使っておらず、文字は Vue が自動で安全にして出す
- **マイグレーションとモデルが一致**している（`alembic check`）。往復もできる
- 依存の部品は `uv.lock`・`package-lock.json` で固定されている

## 4. 確認できていないこと
- 画面の動作確認は、2.5 のとおり行った。ただし、**色・配置の細かい見た目**、**読み上げソフトでの聞こえ方**は、確かめていない（Tab キーでの操作は確かめた）
- 本番に近い環境（AWS、画面の配信）での動作は、確かめていない（デプロイの段階で行う）
