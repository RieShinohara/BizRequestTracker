# 画面設計

画面は、依頼の**表（一覧）**と、**詳細モーダル**（一覧から開くウィンドウ）で作る。参考：Dribbble の Aivia チケット画面。
機能の中身は [機能一覧](functional-requirements.md) を参照。試作は `prototype/` にある。

## 1. 一覧の列
| 列 | 補足 |
|---|---|
| ドラッグの取っ手 | 手動の並びのときだけ使える |
| 優先度 | 色付きのラベル |
| タイトル | 下に、チェックリストの**進み具合**（例：3/6 完了）を小さく出す。チェックリストがない依頼には、何も出さない |
| カテゴリー | |
| 依頼者 | 名前だけ（内線番号は出さない） |
| ステータス | 押すと変更できる。確認待ちのときは、確認先も添える |
| 期限日 | 色分け（[機能一覧](functional-requirements.md) の 4 を参照） |
| QMS | チェックの印 |

受付日、詳細、内線番号は、一覧には出さず、詳細モーダルだけに出す。

### キーボードと読み上げソフト
- **詳細を開く**：行のどこを押しても開く（これまでどおり）。加えて、**タイトルは、Tab キーで止まるボタン**で、Enter で開ける。見た目は、ふつうの文字と同じで、Tab で止まったときだけ枠（基調色）が出る
- **閉じたあと**：モーダルを閉じたら、開いたボタン（タイトル、「新しい依頼」、「カテゴリー管理」）へ、Tab の位置を戻す。Tab で来ていたときだけ、枠を出す（マウスで開いたときは、出さない）
- **読み上げソフト向けの文字**（画面には出さない）：ドラッグの取っ手の説明（ドラッグできないときは、その理由）、期限日の「（期限切れ）」「（3営業日以内）」、QMS の「QMS チェックあり」
- **名前を付けたもの**（読み上げソフトが、何かを分かるように）：すべてのモーダル（「依頼の詳細」「新しい依頼」「カテゴリー管理」「テンプレートの編集：カテゴリー名」など）、チェックリストのチェックボックス（項目の名前）、ステータスの札（「ステータス：確認待ち（押して変更）」。押せるボタンとして伝える）、表の先頭の見出し（「並びを変える取っ手」）。見た目は変わらない。これらは、自動のアクセシビリティ検査（axe-core）のテストで守っている
- **ドラッグ（並び替え）は、マウスの操作のみ**。キーボードでの並び替えは、作らない（使う人は1人。複数人で使うときに、見直す）

## 2. 画面上部の件数
画面の上（タイトルの横）に、依頼の件数を出す（数え方は [機能一覧](functional-requirements.md) の 6 を参照）。
- **ステータス別の件数**：未着手・作業中・確認待ち・完了・ペンディング
- **「急ぎ」の件数**：赤いラベルを1つだけ。1件以上あるときは濃い赤で目立たせ、0件のときは淡い色にする

## 3. 画面の色
- **基調色**：インディゴ（ボタン、チェックボックス、スイッチ、入力欄の選択時、QMS の印）。色を指定しない部品が黒く見えないようにする
- **ステータスの色**：未着手＝灰、作業中＝青、確認待ち＝赤紫（赤っぽいと「急かされる」感じがするため、赤を抑えた色にした）、完了＝緑、ペンディング＝茶
- **優先度の色**：急ぎ＝赤、高＝オレンジ、中＝青、低＝灰
- **文字色**：真っ黒だと強いので、薄めのグレー（`#4A4A4A`）にする
- **フォント**：Noto Sans JP（アプリに同梱。アルファベットも細めで読みやすい）
- **詳細モーダルの「必須」**：入力欄の名前の「必須」は、基調色（インディゴ）の小さな札にして、目立たせる（タイトル・依頼者・期限日）
- 色は設定の1か所にまとめ、あとから変えやすくする

## 4. 詳細モーダルの配置
- **上の段**：タイトル、ステータス、優先度
- **左側（依頼の情報）**：詳細、依頼者（内線番号つき）、カテゴリー、受付日、期限日、確認先、QMS チェック
- **右側（チェックリスト）**：テンプレートを入れるボタン、項目の一覧（チェックを付ける）、項目を足す入力欄
- **下の段**：保存、アーカイブ（アーカイブ中の依頼は、「元に戻す」と「完全に削除」）
- **保存・アーカイブ・削除に失敗したとき**：API が理由（例：「同じ名前の依頼者がすでにあります」「依頼が見つかりません」）を返していれば、その理由を、モーダルの中のエラー欄に出す。理由が読み取れないときは、操作ごとの文（「保存できませんでした。入力を確かめて、もう一度お試しください。」など）を出す
- **文字数の上限**：タイトル 200、詳細 10000、依頼者の名前 100、内線番号 20、確認先 100（確認待ちのとき）、チェックリストの項目 200。超えていたら、保存の前に、「タイトルは200文字までです」のように知らせる
- **一覧からの失敗**：ステータス変更・並びの保存に失敗したときは、画面の下にお知らせを出す。理由があれば、その理由（並びが古いときは、「一覧が古くなっています。開き直してください（一覧を取り直しました）」）
- **保存していない変更があるとき**：入力内容が、開いたときから変わっている（「項目を足す」に書きかけの文字がある場合も含む）と、下の段に「保存していない変更があります」と出し、枠の外を押す・Esc では閉じない。閉じるボタンは、赤い「変更を捨てて閉じる」になる。変更がなければ、これまでどおり、外側・Esc・「閉じる」で閉じる（新しい依頼も同じ。何も入力していなければ、閉じる）

## 5. カテゴリー管理のモーダル
一覧の上、「新しい依頼」の隣にある**「カテゴリー管理」ボタン**から開くモーダル（別のページには移らない）。
- **カテゴリーの一覧**：名前、使っている依頼の数（「依頼 5件」の札）、名前の変更（鉛筆）、削除（ごみ箱）
- **名前の変更**：その場で入力欄に変わる。Enter か、チェックのボタンで保存。同じ名前は、エラーを出して保存しない
- **削除**：使っている依頼が1件でもあるカテゴリーは、ごみ箱を押せない（重ねると理由が出る）。使っていないものは、確認の画面を出してから削除する（テンプレートも一緒に消える）
- **追加**：下の入力欄に名前を入れて、「追加」（Enter でもよい）
- 変更したら、一覧の依頼のカテゴリー名、絞り込みと依頼の選択肢が、すぐ変わる。削除したカテゴリーで絞り込んでいたら、その絞り込みは外す
- 各カテゴリーの「テンプレート」ボタンから、そのカテゴリーの**テンプレートの編集**が開く（6 章）

## 6. テンプレート編集のモーダル
カテゴリー管理のモーダルの上に、重ねて開く。タイトルは「テンプレートの編集：カテゴリー名」。
- **項目の一覧**：番号つき。名前をその場で直せる。右の × で消す。並び替え（ドラッグ）は、作らない（最初の範囲）
- **足す**：下の入力欄に入れて、「足す」（Enter でもよい）。入力欄に書きかけの文字があるまま「保存」を押したら、それも項目として足してから保存する
- **保存**：「保存」を押すと、この一覧が、そのままテンプレートになる（追加・直し・削除を、一度に反映）。空の名前の項目があると、何番目かを知らせて、保存しない。成功したら、閉じる
- **すでにある依頼のチェックリストは、変わらない**（次に「テンプレートを入れる」を押したときから、新しい内容になる）。この説明を、画面の上に書く
- **保存していない変更があるとき**：「保存していない変更があります」と出し、枠の外を押す・Esc では閉じない。閉じるボタンは「変更を捨てて閉じる」になる
