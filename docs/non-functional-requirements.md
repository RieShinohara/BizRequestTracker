# 非機能要件

機能そのものではなく、「どのような条件で動くか」「どのくらいの品質か」を定める。
機能については [機能一覧](functional-requirements.md) を参照。

## 1. 動作環境
- Windows、Chrome ブラウザ（使う人が普段使っているのは Chrome だけ。ほかのブラウザでの動作は、確認しない）
- 利用者のPC内でのみ動作し、インターネットには公開しない
- 例外：学習と動作確認のために、AWS（EC2）に置くことがある。そのときも、入口は自分の IP だけに絞り、不特定多数には公開しない。使い終わったら消す

## 2. データの保存
- 依頼のデータは、データベース（SQLite）に保存する
- ブラウザを閉じても、データが消えない
- 一覧からの変更（ステータス、手動の並び）は、操作した時点で保存される
- 詳細モーダルの変更は、「保存」を押したときに保存される

## 3. 性能・容量
- 依頼の数は、1か月に約20件。通常は約300件（約1年分）、動作保証の目安は**1,000件**（アーカイブ中を含む）
- この件数で、一覧の表示、検索、絞り込み、並び替え、ドラッグが、遅れを感じずにできること
- 1,000件は上限ではない。超えても使えるが、速さは保証しない。枚数が増えたことを知らせる警告は、出さない

## 4. バックアップ
- バックアップの機能（ボタンや画面）は、作らない（対象外）
- データは、SQLite の DB ファイル1つに入っている。このファイルを手でコピーすれば、バックアップになる。壊れたときは、コピーしたファイルを元の場所に戻す
- コピーと復元の手順は、README に書く（アプリを作る段階で書く）

## 5. セキュリティ
- ログイン機能は不要（使う人は1人）
- 外部に公開しない。バックエンドは、自分のPC（`127.0.0.1`）だけで待ち受け、同じネットワークの他のPCからは、つながらない
- AWS に置くときは、入口を自分の IP（`/32`）だけに絞る（`0.0.0.0/0` は使わない）
- パスワード、キー、個人情報は、コミットしない。秘密は `.env`（コミットしない）に書く

## 6. 使いやすさ
- 毎日よく使う操作は、少ない操作回数で行えること
  - ステータスの変更（一覧から、ラベルを押して選ぶ）
  - 依頼の追加
  - チェックリストへのチェック
- 取り返しのつかない操作（依頼の完全な削除）は、実行前に確認の画面を出す
- 期限が近い・過ぎた依頼が、色で見分けられること
- 色は、ステータスや優先度の違いが見分けられ、文字が読みやすいこと

## 7. 権利・データの扱い
- サンプルデータは、すべて架空にする（実在の会社名、人名、実際の依頼内容は、入れない）
- 実際の仕事の依頼内容は、公開リポジトリに入れない。DB ファイル（`*.db`）は、コミットしない（`.gitignore` で除外する）
- 権利が不明な画像や文章は、入れない。画像を使うときは、出典とライセンスを `CREDITS.md` に書く
